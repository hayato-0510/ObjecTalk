# ObjecTalk 鈴鹿高専オープンキャンパス展示 設計

## 目的

鈴鹿高専オープンキャンパス（2日間）で、ObjecTalk を据え置きキオスクとして展示する。中学生が自分で操作し、5学科の代表物体キャラと会話し、持ち込んだ物も登録して話せる。学科ごとの違いや高専生活への興味を持ち帰ってもらう。

来場者は同じ端末に一度しか触れないため、セッションをまたぐ記憶は扱わない。狙いは「目の前の物を起点に、鈴鹿高専の情報や外部情報へアクセスする」体験を見せること。学校案内チャットボットとは差別化する。

## 前提と現状

既存実装で使えるもの。

- `ObjectDetectionScene` と音声会話サブシステム（Realtime API + WebRTC、端末検証済み）
- push-to-talk、顔オーバーレイのアニメーション、展示モード（`exhibitionMode`）
- `fin` ボタンによるシーン再ロード（次の来場者用のクリーンな状態への復帰）
- 画面上の登録データ一括削除ボタン
- 認識パイプライン（埋め込み + AKAZE のインスタンス照合、3枚登録）

既存実装のギャップ。

- `personality_prompt` カラムは定義されているが、登録フローで一度も書き込まれていない。会話はバックエンドの汎用ペルソナ + 高専ナレッジだけで走っている。
- カテゴリ分類器はない。認識はインスタンス照合のみで、未登録の物体は認識できない。
- 登録フローはキオスク前提になっていない（名前と分類を `TMP_InputField` で入力させる）。

## 確定要件

- 据え置きキオスク。中学生が単独で操作する。各ブースへのスタッフ常駐は前提にしない。
- 発話は push-to-talk に固定する。音声フリー入力とサーバー VAD による自動発話開始は使わない。カテゴリ別の提案チップ（タップ質問）を併設する。
- 物体は2系統で扱う。
  - 5学科の代表物体は運営が事前登録する（シード物体）。手書きの性格プロンプトを直接与える。
  - 来場者の持ち込み物体は既存の3枚登録フローで扱う。キオスク向けに簡素化する。性格プロンプトはバックエンドが会話開始時に分類から生成する。
- カテゴリと物体に応じてシステムプロンプトを切り替える。
- バックエンドにツール層を持たせる。鈴鹿高専ナレッジ、天気、Web 検索。LLM が物体と質問内容から自動で選ぶ。
- ツール実行の待ち時間は「調べているね」のフィラーと顔アニメーションで埋める。
- 無操作が続いたらセッションを自動リセットする。手動の `fin` も残す。
- 待機中はアトラクト画面を表示する。
- 入力モデレーションを行い、逸脱した要求は物体キャラとしてはぐらかす。
- ネットワーク断のとき、5学科キャラは定型応答で最低限の会話を成立させる。
- 来場者の登録物は定期的に一括削除する。シード物体は削除対象から除外する。
- 会話内容を端末、SQLite、バックエンドに保存しない（既存方針を継承）。

## 採用方式

既存の `ObjectDetectionScene` と音声会話サブシステムを土台にする。新規に作るのは次の4つ。

- 展示運用の制御（無操作タイムアウト、アトラクト画面、セッションリセット、シード物体の保護）
- バックエンドのツール層と分類別ペルソナ生成
- キオスク向けに簡素化した登録フロー
- カテゴリ別のシステムプロンプトと提案チップ

認識パイプライン（埋め込み + AKAZE のインスタンス照合）は変更しない。VLM による一発識別とカテゴリ分類器は作らない。持ち込み物体は3枚登録で扱う。

## 全体アーキテクチャ（差分中心）

```text
ExhibitionSessionController（新規）
  ├─ 無操作タイムアウト → アトラクト画面 → シーン再ロード
  ├─ アトラクト画面の表示制御
  └─ シード物体の保護（一括削除からの除外）
        │
        ▼
EmbeddingObjectMatcher
  └─ キオスク向け登録フロー（分類プリセット、命名の省略、配置ステップの省略）
        │
        ▼
TalkController / TalkView
  ├─ カテゴリ別の提案チップ
  ├─ ツール実行中インジケータ
  └─ フィラー音声・テキスト
        │
        ▼
ObjecTalk Backend
  ├─ conversation/buildInstructions（分類別ペルソナ、持ち込み物体のペルソナ生成）
  ├─ tools/registry（分類 → 推奨ツールのポリシー）
  ├─ tools/（knowledgeSearch / weather / webSearch）
  └─ moderation（ユーザー入力の事前チェック）
```

## コンポーネント

### `ExhibitionSessionController`（新規・クライアント）

展示運用だけを担当する。会話ロジックと認識ロジックは持たない。

- 会話が `Idle` かつ最後のタッチ操作から一定時間が経過したらアトラクト画面へ切り替える。
- アトラクト画面でさらに操作がなければ `ObjectDetectionScene` を再ロードする。
- 会話中や登録中はタイムアウトを停止する。
- 一括削除の対象からシード物体を除外する判断を持つ。

設定値（Inspector または設定アセット）。

```text
IdleToAttractSeconds = 45
AttractToReloadSeconds = 30
```

### `EmbeddingObjectMatcher`（既存・登録フローの簡素化）

キオスクで中学生が単独で登録を完了できるようにする。

- 分類は自由入力を廃止し、プリセットのボタンから1つ選ばせる（文房具 / 飲みもの・傘 / 電子機器 / 本・紙 / アクセサリ / その他）。
- 名前入力は任意にする。スキップ時は分類名または自動名を使う。
- 目・口の配置ステップを省略する。未配置時の中央デフォルト顔を使う（既存の仕組み）。
- 撮影ガイドに「模様や文字のある面を見せてね」を追加する。`Featureless` で弾かれたときの誘導文を出す。
- このセッションで登録した物体は非シードとして記録する。

### 登録データとシード物体

- `ObjectItem` にシード判定を追加する（`is_seed` 列、または専用テーブル）。
- 5学科の代表物体は事前登録時に `is_seed = true` とする。
- 来場者登録は `is_seed = false`。
- `DatabaseManager` に非シードだけを削除するメソッドを追加する。既存の一括削除ボタンをこの経路に切り替える。

### バックエンド `conversation/buildInstructions`（既存の拡張）

- `objectName`、`category`、`personalityPrompt` を受け取り、固定テンプレートへ組み込む。
- `category` 別のペルソナ断片を持つ。5学科物体は `personalityPrompt` を直接使う。
- 持ち込み物体は `personalityPrompt` が空なので、`category` と `objectName` からペルソナを生成する。
- 固定の安全指示をクライアント入力より優先する（既存方針）。

### バックエンド `tools/`（新規）

- ツールを OpenAI Realtime のセッション設定に function として登録する。
- `knowledgeSearch` — 鈴鹿高専ナレッジ / RAG。
- `weather` — 地点と日付から予報を返す。
- `webSearch` — 一般検索。
- LLM が function を呼ぶ。クライアントはデータチャネルで `function_call` を受け、バックエンドの `/api/tools/invoke` へ転送し、結果を `function_call_output` として返す。
- 代替案として、バックエンドを Realtime のリモート MCP サーバーとして構成し、OpenAI 側でツール呼び出しを完結させる。クライアント改修が最小になる。実装前に遅延と対応状況を検証する。

### バックエンド `tools/registry`（新規）

- `category` → 推奨ツールのポリシーを持つ。
- ツール自体はどの物体でも使える。ポリシーはシステムプロンプトに「この物体では次のツールが特に役立つ」と記述する形で反映する。
- 例。
  - 飲みもの・傘 → `weather`
  - 電子機器 → `webSearch`、`knowledgeSearch`
  - 本・紙 → `webSearch`
  - 5学科物体 → `knowledgeSearch`

### カテゴリ別の提案チップ（クライアント）

- `category` → 提案チップ3〜4個のマッピングを持つ。
- 認識または登録の直後に `TalkView` へ表示する。タップすると push-to-talk と同じ経路で質問を送る。
- 例。
  - 電子機器 —「これで何が作れる？」「プログラミングって難しい？」「AI ってどう動いてるの？」
  - 飲みもの・傘 —「今日はこれ要る？」「明日の天気は？」
  - 本・紙 —「これに何が書いてある？」「似た本ある？」
  - 5学科物体 —「この学科で何を学ぶの？」「高専と普通高校の違いは？」「寮生活ってどんな感じ？」

### ツール待ち時間の演出（クライアント）

- `function_call` を検出したら `TalkView` にインジケータを出す（例「調べているよ」）。
- 短い定型フィラーを再生またはテキスト表示する。
- 顔アニメーションは会話中の挙動を継続する。

### モデレーション（バックエンド）

- ユーザー文字起こしを OpenAI moderation にかける。逸脱時は物体キャラとしてはぐらかす応答へ誘導する。
- ペルソナに「個人情報を聞き出さない、出力しない」「危険な要求には安全な代替か拒否」を明記する（既存方針の再確認）。

### ネットワーク断フォールバック（クライアント + データ）

- 5学科キャラごとに5〜10個の定型応答をローカルに持つ（学科紹介、高専の特徴、寮生活）。
- Realtime 接続に失敗し、対象がシード物体なら、定型モードで最小限の会話を成立させる。
- 持ち込み物体はフォールバックしない。「いまつながらないみたい」と表示する。

## 5学科の代表物体（たたき台）

| 学科 | 物体 | キャラの軸 |
|---|---|---|
| 電子情報工学科 | ノート PC（確定） | ソフト、プログラミング、AI |
| 電気電子工学科 | ブレッドボード上の LED 回路 | ハード、回路、電気 |
| 機械工学科 | 歯車 またはロボットアーム部品 | 動き、設計、ものづくり |
| 生物応用化学科 | 三角フラスコ または試薬瓶 | 実験、反応、分析 |
| 材料工学科 | 金属サンプル または合金片 | 素材、強さ、結晶 |

電子情報をソフト、電気電子をハードに寄せると、中学生に学科の違いが伝わりやすい。最終的な物体選定は各学科の教員に委ねる。

## 登録フロー（キオスク簡素版）

1. 「自分の物を登録する」を選ぶ。
2. カメラに物をかざす。「模様や文字のある面を見せてね」のガイドを出す。
3. 3方向から撮影する（既存）。`Featureless` で弾かれたら誘導文を出す。
4. 名前を任意入力する。スキップ可。
5. 分類をプリセットボタンから1つ選ぶ。
6. 目・口の配置は省略する。
7. 登録を完了し、そのまま会話を開始する。
8. 登録物体は `is_seed = false` とし、定期削除の対象にする。

## 会話開始フロー（差分）

1. 物体を認識する（シード物体）または登録を完了する（持ち込み物体）。
2. `ConversationContext` を構築する。持ち込み物体は `category` を含める。
3. バックエンドが `objectName` と `category` と `personalityPrompt` からシステム指示を組み立てる。
4. Realtime セッションを function ツール付きで開始する。
5. LLM が必要に応じてツールを呼ぶ。クライアントはインジケータとフィラーを出す。
6. 応答を Talk 画面に反映する。

## 運用

- 無操作タイムアウトでアトラクト画面へ、さらに無操作でシーン再ロード。
- アトラクト画面はキャラのループアニメと「物をかざしてボタンを押してね」の案内。
- 来場者登録の一括削除は展示スタッフ用ボタンで行う。1時間ごと、または各日の終わり。
- Realtime セッションの同時数と1セッションの時間上限は既存の `exhibitionMode` を踏襲する。
- ツール呼び出し回数に上限を設ける。

## 見せ玉：複数物体デモ（オプション・手動構成）

1ブースだけ、Arduino と LED と抵抗とブレッドボードを並べて「これで何が作れる？」に答えるデモを置く。これは汎用の複数物体認識ではなく、その場面向けに手動でプロンプトと物体構成を用意する。本設計の必須スコープには含めない。

## テスト戦略

### Unity EditMode

- `ExhibitionSessionController` の無操作タイムアウトとリセット、会話中のタイムアウト停止。
- `category` → システムプロンプト断片、提案チップのマッピング。
- 非シードだけを削除する経路。シード物体が残ること。

### バックエンド

- `category` 別ペルソナの生成。持ち込み物体のペルソナ生成。
- ツールの登録と呼び出し、結果の反映。
- `tools/registry` のポリシーがプロンプトへ反映されること。
- モデレーションが逸脱入力を捕捉すること。
- レート制限とツール呼び出し上限が動作すること。
- 認証情報や会話本文がレスポンスとログへ漏れないこと（既存方針）。

### Android 実機

1. キオスク一連（かざす → 登録 → 会話 → ツール → リセット）を中学生役が単独で完了できる。
2. 行列を想定した連続利用。セッション間で状態が残らない。
3. 「傘 → 明日の天気」でツールが自動で走り、待ち時間が演出で埋まる。
4. ネットワーク断で5学科キャラが定型応答に切り替わる。
5. 特徴の少ない物体（つるつるのペン、無地の水筒）の登録挙動。
6. 逸脱した入力へのはぐらかし。
7. 長時間運用時のメモリ、GC、発熱、音切れ。

## 完了条件

- 中学生が単独で、かざす → 登録 → 会話 → 次の人、を完了できる。
- 5学科キャラが学科の違いを分かりやすく説明する。
- 傘で天気ツールが自動で走り、待ち時間が演出で埋まる。
- 無操作で自動リセットされ、次の来場者がクリーンな状態で始められる。
- 来場者登録物を一括削除でき、5学科物体は残る。
- ネットワーク断でも5学科キャラが最低限会話できる。
- 会話内容が端末、DB、バックエンドログへ保存されない。
- Unity EditMode、バックエンド、Android 実機のテストを通過する。

## 対象外

- セッションをまたぐ物体記憶。
- 来場者ログイン、スタンプラリー。
- カレンダーなどへの書き込みアクション。
- VLM による一発識別、カテゴリ分類器。
- 汎用の複数物体関係理解（見せ玉デモは手動構成で別扱い）。
- 音声フリー入力、サーバー VAD による自動発話開始。
- 管理画面、会話分析ダッシュボード。
